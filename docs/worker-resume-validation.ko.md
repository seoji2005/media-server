# 자막 작업 중단·재개 검증 · 2026-09-29

기준 main은 PR70 병합 커밋 `08b0844371973883137ff83488987376cbc6383b`다. 환경은 [앞선 로컬 검증](windows-local-validation.ko.md)과 같은 PC방 Windows 10 / i5-12400F / RAM 32GB / RTX 3070 8GB이며, 이번에는 모델 설치나 GPU 설정을 변경하지 않았다.

## 확인한 문제와 수정

실제 Windows Job 안의 작업자·FFmpeg를 일시정지한 5회 모두, guardian 종료 대기가 끝난 직후 실제 worker.lock은 아직 점유돼 있었다. 이후 기존 검사 제한 안에서 모두 해제됐다. 이 관찰만으로 사용자의 즉시 재개가 항상 실패한다고 판단하지 않았다.

별도 임시 프로세스로 관찰된 잠금 유지 구간을 길게 만든 재현에서는 문제가 드러났다. 실제 HTTP 처리 경로로 재개하면 기존 감독 루프는 잠금이 남아 있는데 새 guardian/compute를 실행했다. 새 작업자는 잠금을 얻지 못했고 요청은 `failed`로 바뀌었다. 이미 저장된 첫 번역은 남았지만 재개 요청을 다시 해야 했다. 별도 잠금 보유 프로세스는 재현용이며 production 자식이 Windows Job을 이탈했다는 증거가 아니다.

감독 루프가 새 작업자를 실행하기 전에 실제 잠금을 확인하도록 수정했다. 경합 중에는 같은 요청을 `queued`로 보존하고, 잠금이 풀리면 한 번 실행한다. 대기 중에도 원본 감상과 일시정지가 가능하다. 모델·API 호출의 자동 재시도는 추가하지 않았다.

독립 검토에서 초기 수정의 파일 오류 처리 결함을 발견했다. 잠금 파일을 열지 못하거나 저장 경로가 안전하지 않은 경우까지 대기로 남기지 않도록 보완했다. 이 경우 `failed / worker_unavailable`을 표시하고, 자식을 실행하거나 자동 재시도하지 않는다. 경로나 원래 예외 내용은 저장하지 않는다. 보완본 `2581a26c`의 재검토에서는 추가 actionable finding이 없었다.

- 집중 검사: 자막·작업자 종료·새 회귀 45개 통과, 18.855초, exit 0.
- 독립 재검토 검사: 경합 재개 및 오류 경로 3개 통과, 6.917초.
- 실제 Chrome + HTTP + 별도 guardian/compute: 일시정지 버튼 한 번, 재개 버튼 한 번을 눌렀다. 잠금을 3.3초 유지하는 동안 queued/attempt 1/완료 1개가 보존됐고, 영상 36프레임과 기존 한국어 native 자막이 재생됐다. 해제 후 attempt 2/완료 2개로 성공했다. ASR 1회, 이미 완료한 첫 번역 1회이며 중단된 두 번째 번역만 다시 실행했다. 외부 페이지 요청·페이지 오류는 0이었다.
- 서버 프로세스를 종료하고 보완본으로 재시작한 뒤, 완료 상태·attempt 2·자막 2개·이전 한국어 자막을 확인했다. 추가 처리 요청 없이 영상 63프레임이 디코딩됐다. 외부 페이지 요청·페이지 오류는 0이었다.
- 회귀 검사는 저장 전사·해시·첫 번역 batch의 완전 동일성, 기존 자막, 원본 및 관리 사본의 SHA256, 재시작 결과, 중복 생성 없음도 확인한다. 실제 잘못된 잠금 파일 경로와 주입한 unsafe_storage는 명시적으로 실패한다.

Chrome 최초 중단·재개는 `b7b1d24`, 최종 오류 처리 및 서버 재시작은 `2581a26c`에서 확인했다. 최종 통합 검사는 보완된 코드에 수행했다. 초기 회귀 실패와 독립 검토 지적을 성공 기록으로 덮지 않았다.

## 검증 한계와 다음 항목

모델 결과는 합성 FixtureModel을 사용했다. 실제 작업 감독·OS 잠금·HTTP·SQLite·브라우저 재생을 검증하며, 현재 Qwen/Gemini 추론 품질이나 GPU 처리 성능을 입증하지 않는다. 시험용 서버는 종료했다. 본인 PC에서는 실제 영상으로 Qwen→정렬→Gemini, 중단·재개, 장편 품질과 VRAM을 별도 확인해야 한다. 이번 변경은 모델·프롬프트·자막 내용·API 계약·스키마를 바꾸지 않는다.
